# Contribute

1. Search existing records and issues for duplicates.
2. Use an issue form or create a branch in your fork.
3. Change one organization per pull request where practical.
4. Add a primary source for every substantive new claim.
5. State your relationship to the organization in the pull request. Self-submissions are welcome when disclosed.
6. Keep new claims `pending`. A separate reviewer records approval in the pull request.
7. Run `node scripts/validate-data.mjs` and `node scripts/build-registry.mjs`.
8. Open a pull request using the template.

Do not infer political affiliation from donors, investors, geography, or research topics. Record a specific documented policy position separately from political affiliation. Do not add private contact information or unsupported allegations.

A source can support one claim without validating the entire record. State the relevant time period and whether evidence is a self-disclosure. See [evidence policy](docs/evidence-policy.md).

Use `good first issue` for one missing source, `needs evidence` for unsupported claims, and `needs review` for ready contributions. Maintainers must create these labels in GitHub before using them.
